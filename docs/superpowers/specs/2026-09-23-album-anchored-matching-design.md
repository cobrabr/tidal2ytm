# Album-anchored matching design

Date: 2026-09-23. Goal: replace the ISRC-first matcher with album-anchored matching that keeps album mates coherent and picks the correct recording, using source album identity as ground truth and target album round-trips as the resolution mechanism.

## Decisions locked during brainstorming

ISRC matching is dead because song search results carry no ISRC and a bounded song-detail fallback would only burn player requests, so the design never depends on target-side ISRC. Per-track title search stays only as a flagged fallback, never as the primary path, because it structurally scatters album mates across compilations and cannot distinguish remasters, live cuts, alternate mixes, or re-recordings. Grouping is by source album identifier, never by album name, and coherence applies only within one source album group with no cross-group voting, so groups with overlapping tracklists resolve independently in either order with identical results. Extra album-detail calls are acceptable bounded by unique albums with an album-identifier cache and a small inter-call delay, and slower matching is explicitly preferred over manual scattered-track repair. Priority order is album coherence plus correct recording first, with duration-divergent variants of the same work handled as verification rather than the primary signal.

## Architecture

Matching works on album tasks, not track tasks: planning groups the liked source track list by album identifier, each group resolves its single target album counterpart once via album search plus album-detail fetches, maps its tracks inside that album tracklist, and only tracks with no in-album fit fall back to per-track song search flagged as needing review. Single-track groups use the same path because one album resolve still beats blind song search. The winner-takes-group default makes coherence structural: all liked tracks from one source album land on the same target album identifier or fail together into review. The existing atomic plan-write invariant is unchanged: match results merge into the plan file with one metadata recomputation plus one atomic save in a single batch, never per-track rewrite loops.

## Album resolution

Each source album group resolves independently with no shared state across groups. The album query is album plus artist with an album-scoped search and a bounded candidate limit, then the top few album candidates are fetched in detail and cached by album identifier for the run. Album-level scoring uses version-sensitive title similarity that preserves numeral suffixes, parentheticals, and edition qualifiers instead of normalizing them away, strict artist similarity where a rename or side-project mismatch is treated as signal rather than collapsed through aliasing, year proximity with neutral handling of unknown years, and record-type preference for full albums over singles or EPs. Track-support scoring finds every liked track's best fit inside each candidate tracklist on title plus version tokens plus track and disc position plus duration, with a missing title scoring zero rather than neutral so distinctive tracks decide: tracks unique to one edition drag down the competing edition's mean even when shared titles match both, while renumbered shared titles are separated by position plus duration plus artist rather than title alone. The album score combines album-level and mean track fit, the winner takes the group, and a top-two margin below epsilon abstains the whole group to review instead of forcing a silent wrong album.

## Track scorer

One shared scorer serves both album support and final mapping so close calls decide consistently. Title similarity runs on the base title without parentheticals while a separate version similarity scores extracted tokens covering regional or single variants, mix or remix years, remaster markers, mono or stereo markers, live markers, and acoustic markers, where missing-versus-present is a penalty and present-versus-different is a larger penalty so a plain source title never ties a heavily qualified target variant. Artist similarity spans all credited artists strictly with no rename aliasing, track-position exact match is a strong bonus and disc-position exact a smaller one without vetoing renumbered editions, and duration is a double-check combining an absolute delta with a relative component so near-identical durations need version plus position agreement while minutes-apart variants fail outright. Album-title qualifiers score separately from the base album title so the base name can match while the edition suffix still separates. Confidence extends the current breakdown with version similarity, track-position agreement, and album coherence (share of the group on the same target album identifier), and a new album-anchored match method marks in-album hits while the existing methods remain for fallback compatibility so existing plan files still load.

## Data flow

The pipeline is group by source album identifier, then per group resolve album candidates, fetch candidate tracklists through the album cache with delay, score albums, map tracks inside the winner, run per-track song-search fallback only for no-fit tracks, and finally merge everything into the plan with one metadata recomputation and atomic write. Target call cost scales with unique source albums times a small bounded number of album fetches plus one album search each, plus fallback searches only for failures, which keeps rate-limit exposure predictable. No secrets or randomness feed plan content, slug and backup-stamp rules are unchanged, and exit, error-type, and private-import invariants carry over untouched.

## Errors, fallback, and review

No album candidates, album-detail transport failures, or no in-album fit above the floor all route to the same per-track fallback whose results are forced into review with explicit reasons such as no album resolve, no in-album fit, or close album call. Close album margins and close track fits across variants abstain to review by design, which is where rare ambiguous editions should land rather than scattering silently. Narrow auth and transport error handling is unchanged: only the established auth-error tuple is caught around probes while anything else propagates instead of degrading into re-authenticate guidance. The review interface keeps its existing decision keys and gains a group header showing the source-to-target album mapping with coherence fraction and mean confidence so a coherent group can be batch-accepted while split or abstained groups draw attention.

## Testing and quality gates

Tests use fictional artists and tracks plus synthetic identifiers only, with threshold-edge coverage for the duration relative gate, version-token penalties, track-position bonus behavior, album-margin abstention, and an overlapping-tracklist fixture proving independent groups never collapse onto one target album. No tests lock exact colours, glyphs, whitespace, copy, or standard-library internals, and no duplicated threshold suites beyond the edge cases that define the new constants. Gates stay lint check, format check, strict type checking, and the test suite with the enforced coverage floor of eighty percent, run as the continuous-integration sequence before pushing because the pre-push hook can hide order-dependent failures.

## Out of scope

No audio fingerprinting or audio downloads, no external identifier-bridge dependency, no song-detail identifier probe beyond an optional throwaway spike, no cross-group global reconciliation voting, no artist-rename aliasing, no per-track rewrite loops, no plan-file format break beyond the additive album-anchored match method, no transfer or authentication behaviour changes, and no new complexity suppressions beyond the pre-existing matcher suppression which should shrink as the matcher splits.
