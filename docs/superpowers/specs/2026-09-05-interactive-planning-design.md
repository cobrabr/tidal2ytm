# Interactive planning TUI design

Date: 2026-09-05. Goal: bare `tidal2ytm` opens an interactive planning TUI for choosing what to match; `tidal2ytm plan` is removed. Transfer, review, status, and auth stay as they are.

## Decisions locked during brainstorming

Search filters the already-fetched liked-tracks list locally; there is no live Tidal catalogue search. Selections are saved unmatched and matched later through an explicit match action inside the planning TUI. The build adds a new `planning.py` module and leaves `review.py` untouched. Re-match policy: skip transferred, add new ones, prompt about existing ones. The cross-search review screen supports deselect. Artists mode matches performer fields plus title and version, with a spike to check whether `tidalapi` exposes composer credits more granularly.

## Architecture and CLI surface

A new `tidal2ytm/planning.py` module owns the interactive planning TUI. Bare `tidal2ytm` with no subcommand opens it; the `argparse` subparsers become `required=False` and dispatch to planning when `command` is `None`. `tidal2ytm/plan.py` plus its `plan` parser and `cmd_plan` are deleted. Transfer, review, status, and auth keep their current behaviour. The two stale "run `tidal2ytm plan` first" strings in `cli.py:cmd_status` and `review.py:run_review` are repointed at bare `tidal2ytm`. Reused helpers stay where they are: `tidal_source.get_liked_tracks` for the one-time fetch, `matcher.match_track` for matching, `slugs.py` for all slug logic, `plan_io.py` for load, save, backup, and meta. The `_match_result_to_track_dict` converter moves from `plan.py` into `planning.py` with identical logic. `review.py` is not imported by the new module and is not modified beyond its error string.

## Search, selection, and cross-search review

On start the TUI performs the Tidal login, fetches liked tracks once via `get_liked_tracks`, and keeps them as a `list[SourceTrack]` plus a `tidal_id -> SourceTrack` index. All five modes filter that in-memory list in two tiers that reuse the matcher's existing string helpers, so search behaves the same as matching with no new algorithm: tier 1 is normalized substring matching via `matcher._normalize` (case- and diacritic-insensitive), and tier 2 ranks the remaining tracks with `matcher._similarity` (difflib) above a 0.6 cutoff for typo tolerance, ordered substring hits first and then similarity score. Phonetic matching such as Soundex is out of scope: it adds a second string-matching approach for little gain on text that is usually typed or pasted correctly. Everything selects all liked tracks; general matches title, artist, artists list, or album; artists mode matches the performer fields (`artist`, `artists`) plus `title` and `version`, because composer information usually surfaces in the title for classical tracks, and groups hits by artist for bulk select; albums mode matches album name and selecting an album expands to that album's liked songs, never an album entity; songs mode matches title plus version. Results render Tidal-side fields only (artist, title, album, year, duration, track and disc numbers). The search prompt auto-detects pasted Tidal links (`tidal.com/browse/track/<id>`, `tidal.com/browse/album/<id>`, and their `listen.tidal.com` equivalents), and link input bypasses text ranking entirely: a track link resolves to the single liked track with that `tidal_id` and reports a no-library-hit message when the track is not in the liked collection, while an album link resolves via `album_id` and expands to that exact album's liked songs under the canonical album rule, reporting empty when none of its songs are liked. Picking toggles per track, and artist or album rows offer select-all-of-group. The accumulated selection is a `dict[tidal_id, SourceTrack]`, so repeats across searches collapse and the set survives mode switches. A review screen lists the accumulated set grouped by artist, album, then track, with per-row deselect plus clear-all. YTM login does not happen until the match action, so searching and selecting work with Tidal only. Implementation includes a spike to check what `tidalapi` Track objects expose for composer credits: if there is a clean composer or credits field, `SourceTrack` and `get_liked_tracks` are extended to carry it and the artists-mode match set includes it; if not, title-plus-version matching stands and this limit is recorded here.

## Match action and merge policy

The `m` key triggers matching and nothing matches before that. Pressing `m` first asks `[Y/n]`, with Enter defaulting to yes, before matching anything. The first confirmed trigger performs the YTM login through the existing `cli._ytm_login` wiring, including the TVHTML5 client patch. The action loads the existing plan if present, then walks the selection in the legacy plan order (artist A-Z, album year then name, disc then track). Per track: transferred entries are always kept untouched and counted as skipped, including when override mode is on; tracks with no existing entry are matched via `matcher.match_track`, converted with the moved `_match_result_to_track_dict`, and inserted into the artist and album hierarchy with slugs from `slugs.py` deduplicated against the existing slug namespace, while existing `match_id` values never change; existing non-transferred entries whose new result is identical (same `yt_video_id` after normalizing missing to empty, so two unmatched results also count as identical) are kept silently with no prompt; all other existing non-transferred entries follow the override toggle. The override toggle sits on a non-simple shortcut (`ctrl+o`) and shows a persistent, unmissable banner in the TUI header while on: when on, differing re-matches overwrite without prompting, and when off, each differing re-match shows an old-versus-new `[y/N]` prompt covering method, confidence, and video ID. After the loop the TUI calls `update_plan_meta`, takes one `backup_plan` copy on the first write of the session, then calls `save_plan`, and prints new, upgraded, kept, and skipped counts. There is no `--force` flag in the TUI; per-track `y` or the override toggle are the only overwrite paths.

## Plan file and deletion fallout

The TOML shape is unchanged (artists with `match_id`, albums with `match_id` and optional `year`, tracks with the same Tidal, YTM, confidence, and status fields), so transfer, review, and status keep working with no changes. `save_plan` writes through the same header comment. Deleting `plan.py` means deleting its tests if any exist, removing `cmd_plan` and the `plan` parser, making subparsers `required=False`, and updating `README.md` and `AGENTS.md` workflow steps so planning reads as running bare `tidal2ytm` with matching inside it. The first write of a planning session takes a timestamped `backup_plan` copy exactly like `review.py` does.

## Errors, testing, and quality gates

Tidal login failure aborts the TUI with the existing message. YTM login failure at match time shows the existing re-auth guidance and returns to the selection without losing it. Per-track `match_track` exceptions are caught and the loop continues: a new pick is stored as unmatched with `needs_review`, and an existing entry is kept as-is. `Ctrl+C` and EOF quit cleanly; matched and saved work persists, while unsaved session selections are local to the session. Unit tests cover the local filters (each mode, normalization, artist and album expansion to liked songs, empty results), the selection set (add, toggle, deselect, clear, dedup across searches), the merge policy (transferred always skipped including in override, silent-same, prompt path with injected input, override path), and CLI parsing (bare invokes planning, `plan` is rejected). The interactive key loop itself stays manually tested, matching the existing `review.py` precedent. Quality gates stay `ruff check`, `ruff format --check`, `pyright` strict, and `pytest -q`.

## Dependency upgrades

Before implementation, all dependencies are upgraded to their latest versions (`uv lock --upgrade`, resync) and the quality gates are re-run, with the resulting versions recorded in the implementation plan. If a major bump breaks `tidalapi` or `ytmusicapi` call sites, the call sites are adapted within this task; only if adaptation is disproportionate is the dependency pinned back, with the reason noted. The composer-credits spike runs against the upgraded `tidalapi`.

## Out of scope

No live Tidal catalogue search, no matching of non-library tracks, no changes to transfer, review, or status behaviour, no refactor of `review.py` session code, and no new plan file format.
